# 画面に表示する種別を選ぶ（#13）設計

## 目的

登録した駅から乗り、最寄り駅（降りる駅）で降りる。最寄り駅に止まる種別が限られていると、登録した駅を出る電車の中に乗れない種別がある。乗れない電車を Dock と発車一覧に出さないように、駅ごとに表示する種別を選べるようにする。

## ゴール / 範囲外 / 避けること

- ゴール: 駅ごとに選んだ種別の電車だけを、バンド（次発・「次」・本日終了の始発）と発車一覧に出す。
- 範囲外: 特別ダイヤ。行先での絞り込み（#15 で扱う）。新しい種別が時刻表に現れたことを知らせる通知。
- 避けること: 外し忘れで、最寄り駅に止まらない電車が表示されること（乗り過ごしにつながる）。このため**許可リスト**方式にする（選んだ種別だけ表示し、選んでいない種別・新しく現れた種別は表示しない）。

## 制約

- 時刻表ファイルのデータは消さない。絞り込みは表示するときに行う（週 1 回の再取得で時刻表を上書きしても、選んだ種別は残る）。
- 阪急の駅は、追加フォームで保存したあとに時刻表を取得するため、追加の時点では種別がわからない。

## 検討した作り方

1. **「駅を編集」フォームに種別のチェックボックスを追加する（採用）**: 変更が小さく、阪急の駅とファイルの駅を同じ方法で扱える。
2. 阪急の追加フォームに 3 段目を足し、保存前に時刻表を取得して種別を選ばせる: 取得の流れを組み替える必要がある。ファイルの駅には結局 1 が必要なので、1 に作業が上乗せされる。
3. 右クリックに「表示する種別を選ぶ」ページを独立して置く: 編集フォームはまだ 3 項目なので、分ける利点が小さく、ページとコマンドが増える。

## 決めたこと

利用者が決めたこと:

- 許可リスト方式（上記）。
- 種別は「駅を編集」フォームで選ぶ（作り方 1）。候補は取得済みの時刻表に出てくる種別。

Claude が決めたこと（読むときに確認してほしい点）:

- **設定の形**: `stations.yaml` の駅に、省略できる `trainTypes`（文字列のリスト）を足す。
  ```yaml
  - id: kakuu-kita
    ...
    trainTypes: [普通, 準急]   # 書いた種別だけ表示する。省略するとすべて表示
  ```
  - 省略、または空のリストは「絞り込まない（すべて表示）」。既存の設定や、追加したばかりの駅はそのまま全種別が出る。
  - 種別の一致は文字列の完全一致（時刻表の `HH:MM 種別 行先` の種別と比べる）。
  - 検証: 空文字・空白を含むもの・カンマを含むもの・重複はエラー（カンマは、フォームの複数選択の値がカンマ区切りのため）。JSON Schema（`schemas/stations.schema.json`）にも追加する。
- **絞り込む場所**: Core の `NextDepartureCalculator` で、営業日のダイヤを取り出すところ（`GetDepartures`）で絞り込む。これでバンドの次発・「次」・本日終了の始発・発車一覧がすべて同じルールになる。
- **絞り込んだ結果、電車がないとき**: その日のダイヤには電車があるのに、選んだ種別の電車が今日・翌営業日ともにない場合は、「時刻表未取得」とは別の状態にする。
  - バンド: Title `表示する種別の電車なし`、Subtitle `{name} {directionLabel}`
  - 発車一覧: `表示する種別の電車がありません`（「駅を編集で種別を見直してください」）
  - ダイヤ改正で種別名が変わり、選んだ種別がすべて消えた場合に気づけるようにするため。
- **編集フォーム**: `Input.ChoiceSet`（`isMultiSelect: true`、`style: expanded`）を「表示する種別」として足す。
  - 候補の順番: 時刻表のダイヤ（平日 → 土曜 → 休日 → 土休日の順）で最初に現れた順。
  - 選んであるのに時刻表にない種別も、「{種別}（時刻表になし）」として選んだ状態で出し、外せるようにする。
  - 何も選ばずに保存すると、`trainTypes` を消して全種別を表示する（フォームに「何も選ばないと、すべての種別を表示します」と書く）。
  - 時刻表がまだないときは、チェックボックスの代わりに「時刻表を取得すると種別を選べます」と出し、今の `trainTypes` は変えない。
- **追加フォーム**: 阪急の駅の時刻表を取得できたときのトーストに「表示する種別は『駅を編集』で選べます」を足す。ファイルの駅を追加したときのトーストにも同じ案内を足す。
- **ドキュメント**: README の `stations.yaml` の例と、元の設計書（`2026-11-09-station-countdown-design.md`）の §4.2・§6.1・§6.2 に追記する。

## 実装する人に任せること

- `StationConfig` へのフィールドの足し方（record の等値比較でリストが参照比較になる点に注意。設定の変更検知に使っていれば影響を確認する）。
- 新しいバンド状態の名前と、`CountdownFormatter` での文言の組み立て方。
- テスト: Core の xUnit で、絞り込み（次発・「次」・本日終了の始発・一覧）、絞り込んで空になる場合、`trainTypes` の読み書きと検証エラーを確かめる。
