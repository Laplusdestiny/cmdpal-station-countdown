# 駅の時刻表を YAML に書き写す

あなたは、鉄道の駅の時刻表を、決められた形式の YAML に書き写します。
この YAML は「駅カウントダウン」（PowerToys Command Palette の拡張機能）が読み込み、家を出るまでの残り時間の表示に使います。
電車が 1 本抜けたり、時刻表にない電車が入ったりすると、利用者が電車に乗り遅れます。速さより正確さを優先してください。

> **注意（利用者へ）:** 時刻表の著作権は、鉄道事業者などにあります。取得元によっては、時刻表の複製・変換や、AI のサービスへの送信を、規約で禁じています。使う前に、取得元の規約を確認してください。時刻表を AI に渡すかどうかは、利用者が自分で判断してください。

## 対象の駅

- 駅の ID（`stationId`）: **利用者に確認してください。** 駅カウントダウンの「ファイルで駅を追加」で決めた ID（半角英小文字・数字と `-`）です。下の例の `example-station` を、この ID に置き換えて出力してください。
- 駅と方面: 利用者に確認してください。

## 利用者へ: 時刻表の渡し方

- 1 回の変換で扱うのは、1 つの駅の 1 つの方面だけです。駅に複数の路線や方面があるときは、対象の方面の時刻表だけを渡してください。
- PDF はそのまま渡してください。ウェブページは、スクリーンショットか、本文をコピーした文字で渡してください（HTML ファイルをそのまま渡すと、文字化けすることがあります）。
- 平日と土曜・休日などでページが分かれているときは、すべて渡してください。
- 日付を選んで表示する時刻表（「平日」「土休日」の見出しがないもの）では、平日の日付と日曜・祝日の日付を 1 つずつ選び、どの日付の画面かを書き添えてください。土曜が日曜・祝日と同じダイヤか分からないときは、土曜の日付の画面も渡してください。

## 作業の手順

1. 凡例を探して、略号や記号（種別・行先・注記）の意味の対応表を作る。
2. 渡された時刻表がどのダイヤ種別に当たるかを決める（下の「ダイヤ種別」）。
3. ダイヤ種別ごとに、時刻表の時間帯（時）ごとの電車の本数を数える。
4. 電車を 1 本ずつ、下の形式で書き写す。
5. 書き終えたら、書き写した電車の時間帯ごとの本数を手順 3 と見比べる。合わない時間帯があれば、時刻表を読み直して直す。

## 出力の形式

```yaml
# yaml-language-server: $schema=../schemas/timetable.schema.json
schemaVersion: 1
stationId: example-station
services:
  weekday:
    - 05:02 普通 架空台
    - 05:15 急行 架空町
    - 05:15 普通 架空台
    - 24:10 普通 架空台
  saturdayHoliday:
    - 05:30 普通 架空台
```

（上の時刻・種別・行先は形式を示すための架空のものです。）

- `schemaVersion: 1` と `stationId: example-station` は、上のとおりに書く。ほかのキーは書かない（利用者が時刻表の URL を示したときだけ、`sourceUrls:` の下に `- URL` の形で書いてよい）。
- 1 本を 1 行で `HH:MM 種別 行先` と書く。区切りは半角スペース 1 つ。時と分は 2 桁で書く（5 時 2 分は `05:02`）。
- 種別と行先の中にはスペースを入れない（「特急 架空号」は `特急架空号`）。
- **0 時以降（深夜）の電車は 24 時以降で書く。** 0 時 10 分は `24:10`、1 時 5 分は `25:05`。`00`〜`02` 時台の時刻は書かない。この拡張機能は 3:00 で日付を切り替えるので、`00:10` と書いた電車は表示されなくなる。
- ダイヤ種別ごとに、時刻の早い順に並べる。同じ時刻の電車は、時刻表の順のまま並べる。
- 略号や記号は、凡例に従って正式な名前に直す（例: 凡例に「無印＝普通」「◇＝急行」「架＝架空台」とあれば、`普通`・`急行`・`架空台` と書く）。
- この駅が終点で、乗れない電車（当駅止まり）は書かない。
- 特定の日だけ走る電車（臨時列車や「○日運転」などの注記がある電車）は書かず、最後の報告に挙げる。
- 読み取りに自信がない電車は、最も確からしい値で書き、その行の直前に `# 要確認: 理由` のコメントを書く。推測で抜けを埋めたり、ほかの時間帯やほかのダイヤから写したりしない。

### ダイヤ種別

`services` の下には、時刻表にあるダイヤ種別だけを書く。あるダイヤ種別の時刻表を、別のダイヤ種別に写して補わない。

| キー | 使うとき |
| --- | --- |
| `weekday` | 平日の時刻表 |
| `saturdayHoliday` | 土曜と日曜・祝日が同じ 1 つの時刻表（「土休日」「土曜・休日」など） |
| `saturday` | 土曜だけの時刻表（日曜・祝日と分かれているとき） |
| `holiday` | 日曜・祝日だけの時刻表（土曜と分かれているとき） |

- 日付を選んで表示する時刻表では、利用者が書き添えた日付の曜日で決める。土曜の日付の画面がなく、土曜が日曜・祝日と同じダイヤか分からないときは、日曜・祝日の時刻表を `holiday` として書き、「土曜の時刻表がないので、土曜は表示されない」と報告する。

## 回答の形

次の 4 つを、この順に出してください。

1. **YAML**: 1 つのコードブロックにまとめる。
2. **時間帯ごとの本数**: ダイヤ種別ごとに、時（5、6、…、24、25）と本数の表。利用者が元の時刻表と見比べて、抜けや重複を確かめるためのもの。24 時以降は「24（0 時台）」のように元の時刻表の時も書く。
3. **種別と行先の一覧**: 使った種別と行先と、それぞれの本数。凡例の略号から直したものは、元の略号も書く。
4. **報告**: `# 要確認` を付けた電車、書かなかった電車（当駅止まり、特定の日だけ走る電車）、ダイヤ種別の決め方で迷った点。なければ「なし」と書く。

## 検証（コマンドを実行できる AI エージェントの場合）

cmdpal-station-countdown のリポジトリで作業していて、コマンドを実行できるときは、YAML を `example-station.yaml` として保存し、次のコマンドで検証してください。エラーと警告がなくなるまで直してください。

```
dotnet run --project tools/TimetableCheck -- check example-station.yaml
```

終了コードは、問題なしなら 0、エラーがあれば 1、警告だけなら 2 です。警告（0〜2 時台の時刻、並び順の崩れ、同じ行の重複）も、時刻表の読み誤りの疑いなので直してください。出力の後半には、時間帯ごとの本数の表が出ます。手順 3 で数えた本数と見比べてください。

## 利用者へ: できた YAML の使い方

YAML を `%LOCALAPPDATA%\StationCountdown\timetables\example-station.yaml` に保存すると、駅カウントダウンが数秒で読み込みます。誤りが疑われる行があれば、駅カウントダウンの一覧の先頭に「時刻表の警告」が出ます。駅を右クリックして「時刻表の要約」を開くと、時間帯ごとの本数を元の時刻表と見比べられます。
